# Laz Connector

Laz Connector is the local device component for Laz Helper. It runs on the user's computer and provides a loopback-only API. The hosted Render service does not gain access to the computer's filesystem.

## Development run

From the repository root, install the connector requirements and start it:

```bash
python -m pip install -r connector/requirements.txt
python -m laz_connector
```

The connector listens on `127.0.0.1:43179`. On first launch it prints a one-time pairing code. Keep the terminal open while using the connector. The code is consumed once when the browser pairs.

For local development, the connector allows `http://127.0.0.1:8000` and `http://localhost:8000` by default. The Render origin `https://laz-helper.onrender.com` is also allowlisted by default. Override origins with `LAZ_CONNECTOR_ALLOWED_ORIGINS`.

## User workflow

1. Start the connector locally.
2. Open Laz Helper and choose **Connect Device**.
3. Approve the local system pairing dialog; if the dialog is unavailable, enter the one-time code printed by Laz Connector.
4. Use **Permissions** in the connection panel to choose a folder or file and the exact capabilities to grant.
5. Revisit Laz Helper later; the saved pairing token reconnects automatically while the connector is running.

If the connector is missing, use the repository's Releases page. Standalone executable packages are generated by the connector release workflow when a `connector-v*` tag is published. Until a release is published, use the development run above.

## Packaging

The GitHub Actions workflow builds standalone executables for Windows, macOS, and Linux on a `connector-v*` tag. Review the workflow output and test the generated artifact on each target OS before publishing it to users.

## Safety notes

- No grants exist by default.
- The connector binds only to loopback.
- File-changing operations are approval-gated by default.
- Create/move/rename reject destination collisions.
- Delete moves a file to connector quarantine instead of immediately erasing it.
- Native file pickers require a graphical desktop session.
- Do not expose the connector port on a network interface or reverse-proxy it publicly.


## Optional local AI for device Ask/voice

Device-local Ask and task planning use an Ollama-compatible local model. Install Ollama on the same computer, start its local service, and pull the default model with `ollama pull gemma3:1b`. The connector defaults to `http://127.0.0.1:11434/api/generate`; use `LAZ_CONNECTOR_OLLAMA_URL` and `LAZ_CONNECTOR_OLLAMA_MODEL` to change the local endpoint/model. The connector rejects non-loopback model URLs so private device file content is not sent to a remote AI endpoint.

This is optional. The existing hosted workspace question and task-preview modes remain separate. Device-local Ask currently reads bounded UTF-8 text files in the selected folder; PDF and other binary document extraction is not included in this integration block.
